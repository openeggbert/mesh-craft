# M1 · M2 · M3 — AI & Asset Registry Feature Track

Design notes for three related features that together form an asset-pipeline
extension for MeshCraft. Each feature is independently useful; together they
form a full loop: share assets via file includes → persist them in a registry
→ generate new ones with AI.

---

## M1 — `<include file="…"/>` in mc3.xml

### Purpose

Allow one `.mc3.xml` file to import shared assets (definitions, materials,
textures) from another file. Useful for:
- Asset libraries shared across multiple scenes.
- Model registry integration (M2): include library files generated from the
  registry without inlining all content into every scene.

### Semantics

```xml
<!-- scene.mc3.xml -->
<mc3 version="0.3" model="MyScene">
  <include file="furniture_library.mc3.xml"/>
  <include file="materials_pbr.mc3.xml"/>
  <objects>
    <instance name="Chair1" definition="chair" position="0 0 0"/>
  </objects>
</mc3>
```

What `<include>` merges from the referenced file:
- `<definitions>` → definitions available for `<instance>` in the main scene
- `<materials>` → materials available for assignment
- `<textures>` → texture declarations

What is **not** merged (scene-specific):
- `<objects>` — each scene owns its own object tree
- `<lights>`, `<cameras>`, `<environment>`, `<actions>` — scene-level config

Merge order: included content is loaded first; local content in the main file
takes priority over identically-named entries from includes.

Paths are always relative to the file that contains the `<include>` element.

### Cycle detection

Each file tracks the set of files currently being processed on the call
stack (DFS-style). If a file is already in that set, parsing throws
`std::runtime_error("Cyclic <include>: …")`.

Diamond includes (A→B, A→C, B→D, C→D) are handled by a "processed" set;
D is merged exactly once and subsequent includes of D are silently skipped.

### Roundtrip guarantee

`Mc3Document` stores:
```cpp
std::vector<std::string> includes;           // relative paths, in order
std::set<std::string>    includedDefs;       // definition IDs from includes
std::set<std::string>    includedMaterials;  // material IDs from includes
std::set<std::string>    includedTextures;   // texture IDs from includes
```

When saving:
1. `<include>` elements are emitted at the top of `<mc3>`, before other sections.
2. Definitions/materials/textures in the "included" sets are **not** written
   to the file — they live in the referenced library files.

This preserves the include structure across save/load.

## M2 — Model Registry (`modelregistry.sqlite3`)

### Purpose

A local SQLite database storing reusable 3D model assets. Each entry is an
mc3.xml snippet (definitions + materials). MeshCraft can browse and insert
models from the registry without calling an API, and AI-generated models
(M3) are automatically saved here.

### Schema

```sql
CREATE TABLE models (
    id           INTEGER PRIMARY KEY,
    group_name   TEXT NOT NULL,         -- "furniture", "architecture", "nature"
    name         TEXT NOT NULL,         -- "chair", "arch_window", "oak"
    variant      TEXT DEFAULT 'default',-- "gothic", "modern", "damaged"
    tags         TEXT,                  -- "indoor,wooden,pbr" (comma-separated)
    description  TEXT,
    mc3_xml      TEXT NOT NULL,         -- mc3.xml content (defs + materials only)
    thumbnail    BLOB,                  -- PNG bytes, optional
    source       TEXT DEFAULT 'handmade',-- 'handmade' | 'ai_generated'
    created_at   TEXT                   -- ISO-8601
);
CREATE INDEX idx_group_name ON models(group_name, name);
CREATE INDEX idx_tags       ON models(tags);
```

### C++ interface

```cpp
class ModelRegistry {
public:
    explicit ModelRegistry(const std::filesystem::path& dbPath);

    // Browse
    struct Entry { int id; std::string group, name, variant, tags, mc3Xml, source; };
    std::vector<Entry> search(const std::string& query) const;  // matches name/group/tags
    Entry              get(int id) const;

    // Mutate
    int  save(const Entry& e);           // insert or replace; returns id
    void remove(int id);

    // Import into an open Mc3Document
    // Merges the entry's definitions+materials into doc, inserts one <instance> at pos
    void insertIntoScene(const Entry& e, Mc3Document& doc,
                         const std::array<float,3>& position = {}) const;
};
```

### Editor integration

A new ImGui panel "Registry" (dockable, toggle in View menu):
- Search bar → live query against the database
- Results list: group / name / variant / source tag
- "Insert" button → calls `insertIntoScene()`, pushes undo
- "Save Selection to Registry" → serialises selected objects as mc3.xml snippet,
  prompts for group/name/variant, stores in DB

Default database path: `~/.meshcraft/modelregistry.sqlite3`.
Configurable in Preferences.

### Dependency

SQLite amalgamation (`sqlite3.c` + `sqlite3.h`) — bundled in `mc3/vendor/sqlite/`
or fetched via FetchContent (single `.c` file, ~250 KB, no transitive deps).

## M3 — AI API Integration (Claude / other LLM)

### Purpose

Let the user provide a Claude API key and a text prompt. MeshCraft serialises
the current scene (or a selected sub-tree), sends it to the AI with the prompt,
and merges the AI response (a new/updated mc3.xml) back into the document.

Use cases:
- "Fill the room with furniture."
- "Add a row of columns along the east wall."
- "Generate a medieval tavern interior."
- "Make the chair look more ornate."
- "Generate a definition for a stone arch."

### Architecture

```
User types prompt  →  AiAssistant::sendAsync(prompt, currentXml)
                          │
                          │  (background thread, std::async)
                          │
                  Claude API (HTTPS POST)
                  model: claude-opus-4-8
                  system: "You are a 3D scene editor. Return only valid mc3.xml."
                  user: "<current scene xml>\n\nTask: <prompt>"
                          │
                          ▼
                  response: updated mc3.xml
                          │
                          ▼ (main thread, checked in update() loop)
                  pushUndo()
                  Mc3Document::loadFromString(response)
                  merge into document_
                  → optionally save to ModelRegistry
```

### AiAssistant class

```cpp
class AiAssistant {
public:
    std::string apiKey;   // set from preferences
    std::string model = "claude-opus-4-8";

    // Non-blocking: starts a background thread and returns immediately.
    // Poll isDone() each frame; call result() to get the mc3.xml string.
    void sendAsync(const std::string& systemPrompt,
                   const std::string& userMessage);

    bool        isDone()  const;
    bool        hasError() const;
    std::string result()  const;   // valid mc3.xml or empty on error
    std::string errorMsg() const;
    void        reset();
};
```

### HTTP dependency

`cpp-httplib` (single-header, MIT, no runtime deps) + system OpenSSL for HTTPS.

```cmake
FetchContent_Declare(httplib
    GIT_REPOSITORY https://github.com/yhirose/cpp-httplib.git
    GIT_TAG        v0.18.0
)
```

### Editor UI

A dockable "AI Assistant" panel (toggle in View menu):
- Text area: prompt input (multi-line)
- Combo: scope — "Whole scene" / "Selection only"
- "Send" button (disabled while request in flight)
- Progress indicator while waiting
- On success: checkbox "Save result to Registry" (group/name/variant fields appear)
- Status line: last model used, token count if available, error messages

### Context management

Large scenes → large XML → context limit risk. Mitigations:
- "Selection only" scope: serialise only selected objects' subtree
- Strip animations and comments from the serialised context
- Include a condensed schema hint in the system prompt (MC3_FORMAT.md excerpt)

### System prompt template

```
You are a 3D scene editor assistant for the MC3 format.
MC3 is an XML scene format with primitives (box, sphere, cylinder, …),
groups, materials (PBR), CSG operations, extrude, instances, and definitions.
Always return a complete, valid mc3.xml document.
Do not add prose, markdown fences, or explanations — only XML.
The current scene is provided below. Apply the user's instruction and return
the updated scene as mc3.xml.
```

### AI → ModelRegistry integration

When the user checks "Save result to Registry", `AiAssistant` extracts the
`<definitions>` and `<materials>` sections from the AI response and saves them
as a `ModelRegistry::Entry` with `source = "ai_generated"`. The full scene
response replaces the current document.

## Implementation order

```
M1 (include)  →  M2 (registry)  →  M3 (AI)
```

M1 is a prerequisite for M2 (registry can export library mc3.xml files that
scenes include). M2 is helpful but not required for M3 (AI results can be
merged directly without saving to the registry first).
