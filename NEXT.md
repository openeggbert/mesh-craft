## 1. Project Summary

**MeshCraft** is a C++23 3D scene editor for the `.mc3.xml` format — a lightweight
XML-based scene description used by the OpenEggbert project. The editor provides a
Dear ImGui UI with orbit camera, object hierarchy, properties panel, timeline/animation,
gizmos, CSG boolean operations, extrude/path geometry, material editing, AI-assisted
scene generation, and a local model registry.

**Main goal:** Full-featured authoring tool for `.mc3.xml` scenes, analogous to a
stripped-down Blender for the MC3 format.

**Current phase:** Active feature implementation (~80 of 100 plan.md tasks done).
M1/M2/M3 asset pipeline features are complete and hardened. Renderer enhancements
(I1–I7) are the current work area.

**Key architectural decisions:**
- Built on **CNA** — XNA-like C++ runtime (SDL3 + OpenGL ES 3.0 via EasyGL).
  **CNA source must not be modified.**
- Raw GL function pointers (loaded via `SDL_GL_GetProcAddress`) live in the anonymous-
  namespace `BloomGL s_bloom` struct in `MeshCraftApplication.cpp`. Bloom, skybox, and
  any future post-process effects share this struct.
- All UI is **Dear ImGui** (v1.91.6, SDL3 + OpenGL ES 3 backends).
- Scene data (`Mc3Document`) is pure C++ in the `mc3/` sublibrary — no graphics
  dependency. **Public API must not change without auditing `mc3togltf` and all test XMLs.**
- Undo/redo: deep-copy snapshots of entire `Mc3Document` (20-step stack).
- Application split into ~12 `.cpp` files by concern (Mouse, Keyboard, FileOps,
  Commands, Ui*, Anim, WalkMode, UiAi, UiRegistry).

### Recently implemented features (working at runtime, not verified in headless)
- **I3 — Per-object fog:** mixes object color toward fog color by camera distance
  before each draw call in `drawObject()`. Linear and exponential modes.
- **I1 — Background texture:** flat PNG/JPG rendered via `SpriteBatch` before the
  scene, stretched to fill the viewport. Path set in Environment panel.
- **I2 — Equirectangular skybox:** raw GL pipeline in `BloomGL`/`s_bloom`; vertex
  shader reconstructs view ray from camera basis vectors + FOV; fragment shader
  uses spherical UV mapping. Loaded via `stbi_load` (from `mc3togltf_lib`).
  Path set in Environment panel as "Skybox Texture (equirect)".
- **AI prompt caching:** `sendAsync()` now takes separate `systemPrompt`, `sceneXml`,
  `taskPrompt` params; uses structured content JSON with `cache_control: ephemeral`;
  `anthropic-beta: prompt-caching-2024-07-31` header. Scene XML cached 5 min → 10×
  cheaper on repeated edits.
- **AI system prompt from `gen.md`:** `buildSystemPrompt()` loads `gen.md` from the
  project root (tries `./gen.md`, `../gen.md`, next to binary). Full MC3 spec
  (~2 500 tokens) replaces the previous 200-token stub.
- **AI XML repair:** `repairXml()` pre-processes AI response to inject missing `>`
  before child elements (common AI mistake with unclosed opening tags).
- **GLB texture embedding:** `mc3togltf` now reads raw PNG bytes from disk and sets
  `img.as_is = true` → tinygltf embeds images as `data:image/png;base64,...` URIs
  in the GLB BIN chunk. Blender imports GLB with all textures.

### What does not work yet
- **smoke_test segfault** — see Section 4.
- ~~**Bloom (I6):**~~ **FIXED 2026-06-26** — root cause: CNA leaves face culling + stencil enabled, and the VAO-based quad VBO was silently producing no geometry. ## 6. Architecture Notes

### Main modules

| Module | Location | Role |
|--------|----------|------|
| `MeshCraftApplication` | `src/MeshCraft/MeshCraftApplication.cpp` + siblings | Game loop, input, scene state, entire ImGui UI |
| `BloomGL s_bloom` | anonymous namespace in `MeshCraftApplication.cpp` | All raw GL function pointers + handles for bloom, skybox, any future post-process |
| `SceneRenderer` | `src/MeshCraft/Renderer/SceneRenderer*.cpp` (4 files) | Solid + edge + gizmo draw; LOD; BasicEffect; fog mixing |
| `GridRenderer` | `src/MeshCraft/Renderer/GridRenderer.cpp` | XYZ grid lines |
| `EditorCamera` | `include/MeshCraft/Editor/EditorCamera.hpp` | Orbit/pan/zoom; `fovDegrees`, `nearPlane`, `farPlane` |
| `AiAssistant` | `include/MeshCraft/AiAssistant.hpp` + `src/…/AiAssistant.cpp` | Async Claude API; structured JSON with prompt caching |
| `ModelRegistry` | `include/MeshCraft/ModelRegistry.hpp` + `src/…/ModelRegistry.cpp` | SQLite3 model DB; guarded by `MESHCRAFT_HAS_SQLITE3` |
| `Mc3Document` | `mc3/` sublibrary | Pure C++ scene data; XML load/save |
| CNA | `../cna/` sibling repo | SDL3, GL ES 3 context, BasicEffect, SpriteBatch, Input — **do not modify** |

### Renderer draw order (per frame)
1. Panel clear (dark bg)
2. Viewport scissor + bg color clear
3. **I1:** Background flat texture (SpriteBatch, before 3D viewport)
4. 3D viewport set (`glViewport`)
5. **I2:** Equirectangular skybox (raw GL, no depth write)
6. Grid (depth off)
7. Solid scene — `SceneRenderer::draw()` with **I3** fog mixing (depth on)
8. Edge overlay (if enabled)
9. Light/camera/CSG gizmos
10. Transform gizmo, bounding box, locked outlines
11. Bloom emissive pass (if enabled — currently broken)
12. ImGui UI

### Key invariants
- `BloomGL s_bloom` — all raw GL calls go through this singleton. `s_bloom.loadFunctions()`
  must succeed before any `s_bloom.*` function pointer is called. Every code path using
  `s_bloom.*` must check `progXxx != 0` as a proxy for "functions loaded and program compiled".
- Bloom uses `gl_VertexID` vertex shader (no VBO/VAO — bypasses VAO state issues from CNA).
- Skybox still uses `s_bloom.quadVAO`/`quadVBO`. If bloom `initBloom()` runs
  first it sets these; `initSkybox()` creates them only if missing.
- `stb_image` implementation is compiled in `mc3togltf_lib/GltfExporter.cpp`
  (`STB_IMAGE_IMPLEMENTATION`). Include `<stb_image.h>` without the define in app code.
- `Mc3Material` fields: `baseColor[4]`, `roughness`, `metallic`, `emissiveColor[3]` —
  all are attributes in XML, not child elements.
- **Do not push to `master`** directly — work on `develop`.

### Key constraints
- **No CNA source changes** without owner permission.
- **No `${meta-gl_SOURCE_DIR}/include`** in CMakeLists.txt — triggers full CNA recompile.
- **No `Mc3Document` public API changes** without auditing `mc3togltf` and all test XMLs.
- **CLAUDE.md workflow**: always ask user before implementing a plan.md task.
